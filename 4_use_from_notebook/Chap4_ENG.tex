\section{Prerequisites}
\label{sec-notebook-usage}

The scientific backend of \cwv, \script{HydrologicalTwinAlphaSeries} (HTAS), can be driven from a Python notebook \textbf{without QGIS}, through the same public API as the QGIS dialogs. Anything that runs from a notebook today will also run on the future \cwv~server (\cref{chap-dev}). Notebooks live under \script{interface/notebooks/}.

You need:
\begin{itemize}
    \item a checkout of \script{cawaqsviz} with the HTAS submodule populated: \script{git submodule update --init --recursive} (\cref{sec-install-pixi});
    \item \script{pixi} installed (recommended, not mandatory, see \cref{sec-notebook-env});
    \item a readable \cawaqs~output: binaries in the output directory, the \script{ConfigGeometry} \json, and the matching \script{shapefiles}/\script{geopackages}.
\end{itemize}

\section{Setting up the environment}
\label{sec-notebook-env}

From the repository root:

\begin{lstlisting}[language=bash]
pixi install -e notebook          # once: jupyterlab + HTAS, no QGIS
pixi run -e notebook notebook     # local use: Jupyter Lab in interface/notebooks/
\end{lstlisting}

Without \script{pixi}, any virtual environment works (\script{pixi} only adds a pinned, reproducible lock):

\begin{lstlisting}[language=bash]
python -m venv .venv && source .venv/bin/activate
pip install jupyterlab -e external/HydrologicalTwinAlphaSeries
jupyter lab interface/notebooks/
\end{lstlisting}

\section{Running on a remote server}

Recommended: VS~Code \textbf{Remote-SSH}. The kernel runs on the server, next to the data; you edit on your laptop.

\textbf{Once per server}, from the repository root:
\begin{lstlisting}[language=bash]
pixi run -e notebook register-kernel
\end{lstlisting}

\textbf{Every time:}
\begin{enumerate}
    \item \gui{Remote-SSH: Connect to Host} $\rightarrow$ your server. Check that the bottom-left corner shows \gui{SSH: <server>}.
    \item Open the repository folder, then the \script{.ipynb}.
    \item If prompted, install the \textbf{Python} and \textbf{Jupyter} extensions \emph{on the server} (\gui{Install in SSH: <server>}).
    \item \gui{Select Kernel} $\rightarrow$ \gui{Jupyter Kernel\ldots} $\rightarrow$ \gui{CaWaQS (pixi notebook)}.
    \item Run the cells.
\end{enumerate}

\alertwarning{If VS~Code asks to install \script{ipykernel} or \script{pip}, cancel: the wrong kernel is selected (\gui{Python Environments\ldots} instead of \gui{Jupyter Kernel\ldots}), or VS~Code is not connected to the server. Both packages are already in the \script{pixi} environment.}

\alertinfo{Without VS~Code: SSH tunnel. Run \script{jupyter lab --no-browser} on the server, forward with \script{ssh -L 8888:localhost:8888}, open the printed URL locally. Details in \script{interface/notebooks/README.md}.}

\section{Choosing a template}

Both templates share the same parameters cell and \script{layer\_paths} contract; they differ in the HTAS surface (\cref{sec-dev-gates}):

\begin{itemize}
    \item \script{template\_client.ipynb} --- \script{HydrologicalTwinClient}, dialog-shaped API. To \textbf{reproduce a QGIS dialog} (e.g. \script{budget\_barplot}, \script{spatial\_map\_aq}, \script{mask\_hyd\_boundary}). Same surface as the future HTTP server.
    \item \script{template\_developer.ipynb} --- \script{HydrologicalTwin}, verbs \script{fetch} / \script{mask} / \script{transform} / \script{render}. To \textbf{build your own pipeline} or inspect intermediate arrays. The \script{kind=} argument schemas are not documented yet: see \script{handlers.py} in HTAS or copy a call from the template.
\end{itemize}

\section{Workflow}

\begin{enumerate}
    \item \textbf{Copy the template}, never edit it in place (Jupyter Lab: right-click $\rightarrow$ \gui{Duplicate}; VS~Code: copy/paste in the Explorer). Rename it, e.g. \script{seine\_2023.ipynb}.
    \item \textbf{Edit the parameters cell only.}
    \item \textbf{Clear outputs before committing} (they bloat diffs and leak local paths):
\begin{lstlisting}[language=bash]
pixi run -e notebook jupyter nbconvert --clear-output --inplace interface/notebooks/<your_notebook>.ipynb
\end{lstlisting}
\end{enumerate}
