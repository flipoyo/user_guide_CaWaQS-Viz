\section{Pré-requis}
\label{sec-notebook-usage}

Le backend scientifique de \cwv, \script{HydrologicalTwinAlphaSeries} (HTAS), peut être piloté depuis un notebook Python \textbf{sans QGIS}, via la même API publique que les boîtes de dialogue QGIS. Ce qui s'exécute aujourd'hui depuis un notebook s'exécutera aussi sur le futur serveur \cwv~(\cref{chap-dev}). Les notebooks se trouvent sous \script{interface/notebooks/}.

Il faut :
\begin{itemize}
    \item une copie de \script{cawaqsviz} avec le sous-module HTAS renseigné : \script{git submodule update --init --recursive} (\cref{sec-install-pixi}) ;
    \item \script{pixi} installé (recommandé, non obligatoire, voir \cref{sec-notebook-env}) ;
    \item une sortie \cawaqs~lisible : binaires du répertoire de sorties, \json~\script{ConfigGeometry}, et \script{shapefiles}/\script{geopackages} correspondants.
\end{itemize}

\section{Mettre en place l'environnement}
\label{sec-notebook-env}

Depuis la racine du dépôt :

\begin{lstlisting}[language=bash]
pixi install -e notebook          # une fois : jupyterlab + HTAS, sans QGIS
pixi run -e notebook notebook     # usage local : Jupyter Lab dans interface/notebooks/
\end{lstlisting}

Sans \script{pixi}, tout environnement virtuel convient (\script{pixi} n'ajoute qu'un verrouillage reproductible) :

\begin{lstlisting}[language=bash]
python -m venv .venv && source .venv/bin/activate
pip install jupyterlab -e external/HydrologicalTwinAlphaSeries
jupyter lab interface/notebooks/
\end{lstlisting}

\section{Exécuter sur un serveur distant}

Recommandé : \textbf{Remote-SSH} de VS~Code. Le noyau s'exécute sur le serveur, à côté des données ; on édite depuis son ordinateur.

\textbf{Une fois par serveur}, depuis la racine du dépôt :
\begin{lstlisting}[language=bash]
pixi run -e notebook register-kernel
\end{lstlisting}

\textbf{À chaque fois :}
\begin{enumerate}
    \item \gui{Remote-SSH: Connect to Host} $\rightarrow$ votre serveur. Vérifiez qu'en bas à gauche s'affiche \gui{SSH: <serveur>}.
    \item Ouvrez le dossier du dépôt, puis le \script{.ipynb}.
    \item Si demandé, installez les extensions \textbf{Python} et \textbf{Jupyter} \emph{sur le serveur} (\gui{Install in SSH: <serveur>}).
    \item \gui{Select Kernel} $\rightarrow$ \gui{Jupyter Kernel\ldots} $\rightarrow$ \gui{CaWaQS (pixi notebook)}.
    \item Exécutez les cellules.
\end{enumerate}

\alertwarning{Si VS~Code demande d'installer \script{ipykernel} ou \script{pip}, annulez : le mauvais noyau est sélectionné (\gui{Python Environments\ldots} au lieu de \gui{Jupyter Kernel\ldots}), ou VS~Code n'est pas connecté au serveur. Les deux paquets sont déjà dans l'environnement \script{pixi}.}

\alertinfo{Sans VS~Code : tunnel SSH. Lancez \script{jupyter lab --no-browser} sur le serveur, redirigez avec \script{ssh -L 8888:localhost:8888}, ouvrez l'URL affichée en local. Détails dans \script{interface/notebooks/README.md}.}

\section{Choisir un modèle}

Les deux modèles partagent la même cellule de paramètres et le même contrat \script{layer\_paths} ; ils diffèrent par la surface HTAS appelée (\cref{sec-dev-gates}) :

\begin{itemize}
    \item \script{template\_client.ipynb} --- \script{HydrologicalTwinClient}, API calquée sur les boîtes de dialogue. Pour \textbf{reproduire une boîte de dialogue QGIS} (par ex. \script{budget\_barplot}, \script{spatial\_map\_aq}, \script{mask\_hyd\_boundary}). Même surface que le futur serveur HTTP.
    \item \script{template\_developer.ipynb} --- \script{HydrologicalTwin}, verbes \script{fetch} / \script{mask} / \script{transform} / \script{render}. Pour \textbf{construire votre propre chaîne} ou inspecter des tableaux intermédiaires. Les schémas de l'argument \script{kind=} ne sont pas encore documentés : voir \script{handlers.py} dans HTAS ou copier un appel du modèle.
\end{itemize}

\section{Flux de travail}

\begin{enumerate}
    \item \textbf{Copiez le modèle}, ne le modifiez jamais en place (Jupyter Lab : clic droit $\rightarrow$ \gui{Duplicate} ; VS~Code : copier/coller dans l'explorateur). Renommez-le, par ex. \script{seine\_2023.ipynb}.
    \item \textbf{Ne modifiez que la cellule de paramètres.}
    \item \textbf{Effacez les sorties avant de committer} (elles alourdissent les diffs et divulguent des chemins locaux) :
\begin{lstlisting}[language=bash]
pixi run -e notebook jupyter nbconvert --clear-output --inplace interface/notebooks/<your_notebook>.ipynb
\end{lstlisting}
\end{enumerate}
